# Solution design coaching

## Trigger
Use when asked to design a feature, choose technologies, review architecture or clarify a complex integration.

## Steps
1. Establish the problem, user, constraints and measurable desired outcomes.
2. Examine real repository architecture and data contracts; cite files and symbols.
3. Develop alternatives, including a smaller-scope option, and assess costs, operational burden and security.
4. Draw conceptual boundaries and sequence interactions; mark inferred paths as assumptions.
5. Recommend a decision with explicit reasons, reversibility and risks.
6. Produce phased delivery tasks, test strategy, acceptance criteria and rollback guidance.
7. Record the decision locally, using the project's decision and flow guides.

## Output
Problem statement, assumptions, candidate designs, comparison, recommendation, ADR, implementation plan and validation gates.

## Guardrails
Do not copy third-party prompts or hidden proprietary templates. Do not access or transmit private client source outside authorized environments. For destructive or privileged changes request explicit approval.
